## Web App Product Domain Agents

This domain is for building and operating a **web application product** (UI, APIs, data, CI/CD, reliability).

### Roles (agents)

- `web-product-manager`: owns outcomes, scope, priorities, acceptance criteria.
- `web-system-architect`: short, high-signal architecture review and risk tradeoffs.
- `ux-ui-designer`: user flows, IA, interaction design, visual direction.
- `frontend-engineer`: SPA/SSR, performance, accessibility, client architecture.
- `backend-engineer-web`: APIs/BFF, security, business logic, persistence.
- `fullstack-engineer-web` (optional): cross-cutting delivery across FE/BE.
- `qa-engineer-web`: functional/exploratory testing, release confidence.
- `test-automation-engineer-web`: e2e/integration suites, CI signal quality.
- `devops-sre-engineer-web`: environments, CI/CD, observability, reliability.

### Typical interactions (default “product team loop”)

1. `web-product-manager` writes a short problem statement + acceptance criteria.
2. `ux-ui-designer` proposes user flows/wireframes; aligns on constraints.
3. `frontend-engineer` + `backend-engineer-web` propose a solution approach.
4. `web-system-architect` performs a **brief architecture review** (risks, tradeoffs, missing NFRs).
5. `qa-engineer-web` defines test strategy for the change; `test-automation-engineer-web` turns it into automated suites.
6. `devops-sre-engineer-web` ensures CI/CD, environments, and monitoring are ready.

### Key skills commonly used

- `api-design`, `architecture-review`, `testing`, `ci-cd`, `security-review`, `log-analysis`, `performance-tuning`
